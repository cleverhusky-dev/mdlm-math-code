# mdlm-math-code

面向数学推理的掩码扩散语言模型后训练实验。模型接收一道数学题，生成 Python 函数，评分器执行函数，用返回值与标准答案比较。工程包含从预训练 MDLM 出发的监督微调（SFT）、GSM8K 测试，以及在微调模型上进行的 diffu-GRPO 强化学习。

## 变量命名对解题正确率的影响

第一次 SFT 后，验证集去噪损失从 1.1069 降到 0.1279，但答对的题目从 47 道降到了 8 道。检查错误程序时，我们观察到了变量引用不一致。实验 12 因此统一了局部变量名，同时保留题目、计算逻辑、解法数量和训练顺序。例如，训练题 `train:0` 的两份代码都计算出 72：

| 原有命名（实验 8） | 统一命名（实验 12） |
| --- | --- |
| `clips_april = 48` | `x_1 = 48` |
| `clips_may = clips_april / 2` | `x_2 = x_1 / 2` |
| `total_clips = clips_april + clips_may` | `x_3 = x_1 + x_2` |

两组实验各自从相同的预训练 EMA 权重出发，在同一批 12,288 条参考程序上训练 5 轮，峰值学习率均为 `1e-4`。在 639 道验证题上，以温度 1、32 步去噪生成答案，最佳检查点的成绩从 **48/639（7.51%）提高到 121/639（18.94%）**。在一道阅读速度题上，实验 8 生成的程序引用了未定义的变量，实验 12 生成的程序算出了正确答案 72。[两份程序对照](results/sft/examples.md)

## GSM8K 官方测试集

在同一组 1,319 道题上，每种设置每题生成一份程序。SFT 使用实验 12 在验证集选出的第 960 步模型。

| 温度 | 去噪步数 | 预训练模型 | SFT 模型 |
| ---: | ---: | ---: | ---: |
| 1 | 32 | 6.29%（83 题） | 15.54%（205 题） |
| 0.1 | 32 | 20.39%（269 题） | 30.25%（399 题） |
| 0.1 | 128 | 29.49%（389 题） | **36.01%（475 题）** |

训练轮次、采样步数、学习率、数据回放、单解与多解的对照，以及实际生成的代码样例，见 [SFT 结果](results/sft/README.md)。

## 强化学习

从实验 12 的 SFT 模型出发，每道训练题生成 8 份程序，执行正确奖励为 1，其余为 0。以相同解码设置（温度 0.1、128 步）评估，验证集正确题数从起点的 290/639 提高到第 500 步的 308/639，第 1,000 步回落到 294/639。RL 的实验结论限于验证集，官方测试集的结果见上表中的基座与 SFT 对比。[RL 验证曲线与计算开销](results/rl/README.md)

## 使用工程

| 入口 | 内容 |
| --- | --- |
| [SFT](sft/README.md) | 准备输入、构造数据集、运行实验 0–12、评测官方测试集 |
| [RL](rl/README.md) | 准备 SFT 初始化权重、生成候选程序、按执行奖励更新与验证 |
| [实验记录](docs/experiments.md) | 各次实验的研究问题、控制变量、结果与局限 |
| [实验结果](results/) | 可直接查看的指标和样例 |

原实验使用 Linux、Python 3.12、PyTorch 2.6 和两张 RTX 4090（24 GB）。可先阅读结果，再按 SFT 工程的说明准备数据和预训练权重。复跑 RL 时，将所选 SFT 权重及其身份信息传给 RL 启动器。训练产生的权重和临时文件写入本地运行目录。

模型及采样实现沿用 [s-flm](https://github.com/jdeschena/s-flm/tree/30def79976ca3b1cdcb5fcbfa0165524e44001de) 的 MDLM 配置。上游代码及数据的许可证文本见 [licenses/](licenses/)。
